# News cover design

Project root: `C:\Users\user\Downloads\New folder\ai-news\`

Slide 1 is the only thing that stops a scroll, and it is **always generated by Nano Banana
Pro** (`gemini-3-pro-image`) — never composited locally. This skill decides *what* to
generate, from the news, before spending the call.

**The cover must not default to navy.** It did for months, because a shared style clause
appended "Deep navy studio backdrop" to every prompt and silently overrode each recipe. A
launch should read bright; a lawsuit should read dark. Palette is a story decision.

---

## The two axes

Never invent art direction freeform — this publishes automatically with no human review,
and freeform is where drift comes from. Make two **classifications** instead:

- **`recipe`** — WHAT is in frame: `person` · `product` · `money` · `policy` · `research`
- **`story_type`** — HOW it is lit and coloured: `launch` · `policy` · `people` ·
  `research` · `money` · `conflict`

They are orthogonal. A launch can star a person or a product; a conflict can be a face or
an empty corridor. Both tables live in `ai-news/design/covers.json`; the palettes are
written out in [references/palettes.md](references/palettes.md).

## Instructions

### Step 1: Get the story, and verify it

Work from a spec file in `ai-news/state/` if one exists. If given only a topic, research it
first — **every claim needs ≥2 independent credible sources** in `sources_verified`. Do not
duplicate the `ai-news-run` skill's quality gate; that decides *whether* to post, this
decides *how it looks*.

Extract, from the sources rather than from memory: the company, the product name, the person
(if a named individual drives it), the real objects in the story, and the company's brand
colour (`mark_color`).

### Step 2: Classify

Pick one `recipe` and one `story_type`. Ask what the news *is*, not what would look nice:

- A model or feature ships, and the news is good → `launch`
- A regulator, court or government acts → `policy`
- A person is appointed, leaves, or is profiled → `people`
- A benchmark, paper or safety finding → `research`
- Funding, valuation, acquisition, compute spend → `money`
- A lawsuit, outage, incident or resignation under pressure → `conflict`

If two fit, choose the one a reader would say the story is *about*. A funding round used to
buy chips is `money`, not `launch`.

### Step 3: Write the art direction into the spec

Set in the spec's `cover` block:

```json
{ "recipe": "person", "story_type": "launch",
  "subject_ref": "output/person.jpg", "mark_ref": "assets/logos/claude.png",
  "company": "claude", "logo_color": "#D97757",
  "elements": "<story-specific props, 1-2 sentences>" }
```

`elements` carries the real objects from the news. **Keep it palette-neutral** — writing
"drifting through the dark air" inside a `launch` fights the bright background it is paired
with, and the model splits the difference into mud.

Optional: `keyart` (the product's real launch art via `portal.py`), `palette` (an explicit
override that beats the table — use sparingly), `band_edge` (`hard` / `fade`).

### Step 4: Generate

```bash
python scripts/gen_cover.py --spec state/<story>.json --story-type <type>
```

It builds the prompt, calls Nano Banana Pro (~$0.134), writes `cover.background`, sets
`cover.band_edge` from the story type, and turns on `ai_note` when a real person's photo was
a reference. Check with `--dry-run` first if unsure — the printed prompt must contain the
story type's background wording and **no navy instruction at all**.

Then render: `python scripts/make_carousel.py --spec state/<story>.json --outdir output/<id>`

### Step 5: Verify — do not skip this

1. **Read the rendered cover back as an image.** A prompt that looks right routinely
   produces a frame that is not. Check: the head is not cropped, the palette actually
   matches the story type, composited elements are not sitting on the subject's face.
2. `python scripts/qa_check.py --dir output/<id> --spec state/<story>.json` must PASS.
3. If the palette came out dark on a `launch`, the direction was contradicted somewhere —
   look at `elements` first.

## Rules

- **Never generate the cover locally.** Owner instruction: slide 1 is always Nano Banana Pro.
- **Never ask the model for text or logos.** Every word is typeset by our template; the
  company mark is composited from a vector.
- **Composited elements go in negative space.** The person is baked into the generated
  frame, so anything composited paints *over* them — never across the face.
- **A key-art portal must hold something real and identifiable**, fetched from the
  announcement page. If the page has none, omit the portal rather than filling it with
  decoration.
- **Bright covers use a `hard` band edge**, dark ones use `fade`. A fade over a light lower
  third reads as mud.
- The full standing ledger is `ai-news/design/rules.md` — read it before changing anything
  structural, and append a rule whenever the owner rejects something.

## Layout — the axis that was missing (Sep 2026)

For months every cover was the same picture: a CEO, chest-up, centred, facing the lens, with
a logo disc in the corner. The cause was one sentence inside the `person` recipe, which read
*"Chest-up, centred, looking directly into the lens"* — description that the model took as
instruction. Five recipes existed; `person` won every time and the other four were never
generated once. The table built to create variety produced none.

So composition is now its own axis. `design/covers.json` has a **`layouts`** block:
`portrait_disc`, `portrait_offset`, `wordmark_hero`, `object_held`, `environment`, `duo`,
`no_subject`, `stack`. Pass `--layout` to `gen_cover.py`, or set `cover.layout`.

**Three rules, in order:**

1. **Pick the layout from the NEWS.** A partnership is `duo`. A named model launch where the
   name is the hook is `wordmark_hero`. A policy or an outage with no protagonist is
   `no_subject`. Someone backing a thing is `object_held`. Scale or consequence is
   `environment`.
2. **Never repeat the layout used in the last 3 posts.** Read `state/runlog.jsonl` and record
   the layout on every run. This is mechanical on purpose — the old system collapsed because a
   default could quietly win, and a judgement call at 2am is exactly how that happens again.
3. Recipe still says what is in frame; story_type still says how it is lit. Layout only moves
   the camera, the gaze and the marks.

### Marks

`cover.marks` is a LIST, so a cover can carry two or three overlapping logos for a
partnership. Each entry takes `company` (vector or raster from `assets/logos/`) or `ref` (a
path), plus `size`, `left`, `top`, `bg`, `color`, and `bare: true` to drop the disc and set
the mark loose on the art. `cover.wordmark` sets the product name as large display type, with
`wordmark_color` — **ink on a bright cover, cream on a dark one, or it disappears.**

### How far a scene may go

The owner's decision, Sep 2026, taken against the council's advice and recorded here so it is
not silently re-litigated: **match the reference accounts' visual boldness.** Surreal,
symbolic and dramatic composites around a real person are in scope.

Three limits remain, and they are about defamation and publicity rights rather than taste:

- Never depict a real person committing a crime or doing something disgraceful they did not do.
- Never set a fabricated quotation inside the image.
- Never stage a photoreal, documentary-looking depiction of a news event that did not happen.
  Symbolic and obviously-illustrative is fine; something a viewer would take for a photograph
  of a real event is not.

Every cover of a real person keeps the caption's synthetic-media disclosure and CC-BY line.
